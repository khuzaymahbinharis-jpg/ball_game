Track the Game — implementation notes (chronological)
=====================================================

2026-08-30 — Started from an effectively empty repository. The non-negotiable boundary is that semantics come from a VLM, while classical methods may only associate localizations afterward. I avoided YOLO/SAM/detector dependencies entirely and wrote this boundary into AGENTS.md so later work does not accidentally erode it.

I chose normalized boxes for players because an under-foot marker needs the bottom-centre, while boxes retain more future drawing/tracking information than a single point. The ball is a point for now. Responses have frame IDs, per-object confidences, team, and a single possession flag. A dependency-free strict parser rejects unknown keys, bad types, impossible boxes, and inconsistent ball fields. Pydantic was considered, but a small explicit parser keeps the scaffold understandable and install-light. A generated JSON Schema could be added when the actual provider's structured-output dialect is known.

The ruler is a new canvas with top/left margins and decimal ticks. Importantly, reported values describe the original content in normalized 0–1 coordinates, not the larger ruled bitmap. This convention must be repeated in the real prompt. The original image is copied and remains untouched. Rulers are toggled in configuration for a clean ablation.

For sampling I used every N frames plus the final frame. It is predictable, exposes a single useful ablation parameter, and bounds VLM calls. It does not react to scene cuts or unusually fast play; adaptive sampling is a later experiment only if evidence supports it.

For identity I started with explainable greedy nearest-neighbour association at players' foot points, with a maximum normalized distance and optional hard team constraint. IDs are created by the tracker, not trusted from independent VLM calls. I considered Hungarian assignment and a Kalman filter, but they add dependencies/state before there is real footage showing greedy conflicts. Greedy matching can switch IDs at crossings, fail after camera motion, and cannot model velocity. Tracks have a configurable short missed-anchor memory, though interpolated output currently includes only tracks observed at both endpoints.

Between anchors I linearly interpolate boxes, confidence, and ball positions for IDs present at both ends. Possession switches at the temporal midpoint. This is deliberately transparent, but is weak under curved motion, camera cuts, occlusion, and rapid possession changes. Tomorrow's qualitative failures should decide whether propagation, optical flow, or motion models are justified.

Pillow drawing uses wide colored ellipses below feet rather than debug boxes: cyan Team A, red Team B, a yellow possession pointer, and a conspicuous ball ring. Debug IDs are optional. Scale derives from frame size, with minimum radii for readability.

The mock provider is deterministic and explicitly ignores pixels. That makes end-to-end tests meaningful for data flow and identity persistence without pretending detection occurred. No API adapter, key lookup, network request, measured price, latency, or visual-success claim was added tonight.

Experiment logs are append-only JSONL. Unknown real measurements stay null rather than being invented. Configuration is nested so tomorrow's one-variable-at-a-time ruler, sampling, model, and tracking ablations are straightforward. The ffmpeg boundary handles local decoding/encoding but audio preservation remains future work.

2026-08-31 — Prepared the first real experiment without invoking the VLM. I located the downloaded Spurs/Thunder source by filename prefix and trimmed 3:11–3:41. The source was 59.94 FPS, so I intentionally normalized the development clip to exactly 30 FPS: 900 frames and 30.000 seconds. The clip remains ignored by Git.

I selected the deterministic midpoint, frame 450 at 15.000 seconds, rather than using semantic frame-selection logic. The untouched frame is 1920×1080. The prompt-only copy adds 64-pixel top and left rulers, producing 1984×1144, with readable 0.0–1.0 ticks that never overwrite source pixels.

The structured contract now makes ground points explicit instead of deriving them only from boxes. It also carries team confidence, a ball center plus optional box, a possession reference that must match a returned player, and uncertainty notes. The strict parser additionally checks unique player IDs and referential integrity. Tracking and drawing now consume the explicit ground points.

I added a Gemini 3.1 Flash Lite OpenRouter adapter using structured outputs, base64 PNG input, minimal reasoning, and returned usage/cost parsing. It loads only the repository-root `.env`, keeps the key out of configuration and logs, and makes exactly one HTTP attempt. The Test 1 runner requires an explicit approved call count of one; preparing artifacts cannot trigger inference. A mocked transport verifies request shape, schema validation, usage extraction, and the no-retry behavior.

The experiment record now reserves the requested run, validation, cost, latency, human-evaluation, and later tracking fields. The real run will preserve the validated JSON and render Team A/B/uncertain markers, debug IDs, ball highlight, and possession marker onto the original image with Pillow. No paid call or quality claim has been made.

2026-08-31 — After explicit approval, I executed exactly one Test 1 request with no retry. Google AI Studio served the configured Gemini 3.1 Flash Lite model. Human quality fields remain null so the interface result is not misrepresented as measured accuracy.

2026-09-02 — Prepared full-clip Test 2 without paid inference. I chose three-second anchors plus the exact final frame: 11 calls over frames 0, 90, 180, 270, 360, 450, 540, 630, 720, 810, and 899. The verified 1080p, 900-frame, 30-second local output now takes 16.18 seconds. A scaled quality-check frame kept the team, possession, ball, and debug-ID markers readable.

All 11 anchors are prepared locally. The paid runner uses one bounded 11-request parallel wave, zero automatic retries, per-anchor JSONL records, batch summary metrics, and a duplicate-run refusal. 2026-09-02 — After explicit approval, Test 2 attempted exactly 11 calls in one parallel wave and made no retries. Nine anchors validated; frames 630 and 810 failed strict schema validation. The nine successful records contain 23,289 input tokens, 11,509 output tokens, and $0.02308575 known cost. Because the original adapter discarded response metadata when validation failed, the true batch cost remains unknown and must be reported as at least that amount.

The first and last anchors were valid, so I used only the saved successful responses to render a degraded full-clip result locally without another API call. Visual inspection of frame 450 exposed an interpolation bug: endpoint frames retained only tracks shared with the preceding anchor. I fixed interpolation so exact anchors preserve their complete detections, added a regression test, and rerendered. The final file is 1080p, 30 FPS, 900 frames, 30.000 seconds, and retains source audio. API batch time was 11.13 seconds, final rendering 10.61 seconds, and their measured sum 21.74 seconds.

The batch produced 21 unique baseline track IDs, evidence that three-second nearest-neighbour association is not maintaining five-player identities reliably across the clip. This is an operational count, not a ground-truth ID-switch metric; human quality and ID-switch fields remain null. I also changed the adapter so future schema failures preserve raw invalid output plus usage, cost, model, provider, and latency metadata. Twenty-two local/mock tests now pass.
